## Release Theme

**Self-update and trustworthy diagnostics** — v0.8 widened APS to twelve
harnesses; v0.9 makes the tooling that serves them honest. The CLI can now
upgrade itself, the bundled `plan-doctor` skill judges plans against the
documented status vocabulary instead of a stricter private convention, and the
last known three-way lockstep gap closes so a malformed release plan cannot
slip past the fallback CLIs. The through-line is diagnostics you can act on: a
warning that fires on every file in a healthy plan is noise, and a rule that
exists in only one of three implementations is not a rule.

## What Ships

### Distribution (CLI)

Self-update lands on `aps update --global`, leaving project `update` untouched.

| Area          | Detail                                                                                                                                                               |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Self-update   | **`aps update --global`** upgrades the machine-wide CLI at `$APS_HOME/bin` (default `~/.aps/bin`) from GitHub releases (CLI-003, `f945038`)                           |
| Fail-closed   | `--global` is rejected alongside a project dir, symlink payloads in release archives are refused, and an unreadable native binary fails closed rather than silently (`7f50c9f`) |
| No downgrades | Bash and PowerShell `--global` never overwrite a native binary with the script runtime                                                                               |

**APS modules:** [cli-redesign](../modules/cli-redesign.aps.md) (6/7 work
items done — CLI-002 remains, gated on TEAM).

### Diagnostics (plan-doctor)

The bundled skill was unusable on a healthy consumer plan: roughly 385 warnings
fired on a plan with no real defects.

| Area              | Detail                                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Status aliases    | Status is normalised through the documented alias table (`Proposed` → `Draft`, `Done` → `Complete`) before W03/W04/W05/W07 evaluate |
| Terminal deps     | W04 counts `Done` as terminal alongside `Complete`, `Merged`, `Released`, `Shipped`                                        |
| Filename prefixes | The "no `NN-` prefix" half of W02 is demoted to a new Info code, reported once per directory with a count                  |
| Local conventions | A consistently-applied undocumented status (`Archived` on archived index rows) reports under its own Info code, not W03    |

**APS modules:** [continuous-improvement](../modules/continuous-improvement-backlog.aps.md)
(CIB-005). Closes
[#132](https://github.com/eddacraft/anvil-plan-spec/issues/132) / ISS-010.

### Validation parity (three-CLI lockstep)

Release-plan lint rules existed in the Rust linter only, so the fallback CLIs
never discovered `plans/releases/v*.md` at all.

| Area      | Detail                                                                                                    |
| --------- | --------------------------------------------------------------------------------------------------------- |
| Discovery | The bash and PowerShell linters now find `plans/releases/v*.md`, excluding `README.md` and the template   |
| Rules     | R001–R004 ported with identical codes, severities, and messages; all three CLIs agree on findings and counts |
| Regression | Release fixtures in the shared parity suite pin the three-way byte identity; the harness's findings regex now matches `R` codes, which it previously dropped |
| Manifests | Every bash rule module sourced by `bin/aps` now ships in all fourteen installer/updater manifests, with a test deriving the list from `bin/aps` itself |

**APS modules:** [continuous-improvement](../modules/continuous-improvement-backlog.aps.md)
(CIB-006). Satisfies D-039 and supersedes REL-003's Rust-only rationale.
Closes ISS-011.

## Success Criteria

- [ ] `aps update --global` upgrades a global install on all five release targets
- [ ] `plan-doctor` reports zero warnings on a structurally healthy plan that
      uses `Done` / `Proposed` statuses
- [ ] `aps lint plans` reports identical findings under Rust, bash, and PowerShell
- [x] All channels publish 0.9.0 (GitHub release, crates.io, Scoop ×2)

## Risks

| Risk                                                        | Impact | Mitigation                                                                                             |
| ----------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------ |
| Self-update replaces a working binary with a broken one     | High   | Fail-closed on unreadable binaries and symlink payloads; script runtimes never overwrite a native install |
| The plan-doctor fix only reaches users on a release          | Medium | The skill bytes are embedded in the binary, so this cut is the delivery mechanism — no consumer patching |
| Ported lint rules drift from Rust again                      | Medium | Release fixtures in the shared parity suite fail CI on divergence, rather than relying on review        |

## Out of Scope

- **`aps release` (REL-005)** — deferred; the top-ranked Ready item, and the
  tool that would have mechanised this cut's own closeout.
- **Archive backfill for v0.4.0–v0.8.1 (ISS-012)** — deferred to REL-005 rather
  than reconstructed by hand, which would risk fabricating attribution.
- **`aps upgrade` as a verb** — stays reserved until bash `upgrade` is only a
  `migrate` alias (D-CLI-a).
- **CLI-002 profile-aware vocabulary** — gated on the TEAM coordination plane.
